# K8s worktree scope redesign — no runtime fallbacks

Goal: k8s resources get the same scope-driven, deterministic worktree treatment
local_resource already has — instantiation, build lineage, live update, and
service routing all derive from `scope=` at load/stamp time. No runtime `if`
reinterpretation anywhere in the apply path.

## Context

- The fork already has the shared scope seam (uncommitted):
  `internal/tiltfile/scope.go` — `scope="all"|"main"|"worktree"` parsed by
  `local_resource`, `k8s_yaml`, and `k8s_resource`; `scopeInstantiates`
  gates per-run instantiation. The helm example runs end-to-end with clones
  (additive siblings: `api`, `api-wt-wt-a`, `api-wt-wt-b`), per-worktree image
  lineage, scoped live update, and distinct ports (30000-30002 live-verified).
- Rejected design element (this session's stopgap): the runtime fallback in
  `internal/controllers/core/kubernetesapply/reconciler.go:568-591` —
  `if !replaced && spec.Worktree != ""` retries injection with the stable
  selector (scoped minus `-wt-<worktree>` token). This is invisible,
  order-dependent matching. The user rejected it: never acceptable.
- ImageMap identity for worktree runs is repo-scoped (selector
  `wt-helm/api` → `wt-helm/api-wt-wt-a`; ImageMap CR
  `wt-helm_api-wt-wt-a`), pinned by `internal/tiltfile/worktree` boundary
  tests. The build side tags in-cluster images under the scoped repo.
- The helm chart renders the STABLE repo (`wt-helm/api:latest`); today the
  fallback bridges that gap at apply time. The redesign moves the bridge into
  the deterministic stamp mutation.

## Target Tiltfile (what the user sees)

`examples/worktrees-helm/Tiltfile` — a PLAIN single-tilt Tiltfile. Vanilla
names only: no prefixes, no worktree names, no chart-name hacks. Duplication
into worktrees is the default; the author marks only the exceptions. Every
clone name, image lineage, port, and Service DNS is autogenerated by Tilt.

```python
# -*- mode: Python -*-
#
# Tilt executes this file once for the main checkout and once for every
# .worktree/<name>/ checkout. This is a plain Tiltfile: no prefixes, no
# worktree names, no branching. Resources are duplicated into every
# worktree automatically, with autogenerated clone names.

worktree_config(port_range=(30000, 30100))

allow_k8s_contexts(["orbstack", "docker-desktop", "kind-orbstack", "kind-kind"])

# Vanilla names — exactly what a single-tilt setup needs. The ONLY coupling
# is upstream's own: the build ref must match the image name the chart
# renders ("api"). Each run builds from its own checkout; a worktree run's
# build gets autogenerated image lineage and live-updates only its pods.
docker_build(
    "api",
    "api/",
    dockerfile="api/Dockerfile",
    live_update=[
        fall_back_on(paths="api/go.mod"),
        sync("api/", "/app"),
        run("cd /app && go build -o server .", trigger="api/go.mod"),
    ],
)

# Exception 1 — "don't duplicate this": instantiate once, in the main run.
# Worktree clones mount the Secret; they never recreate it.
k8s_yaml(local(["bash", "env-to-secret.sh"], quiet=True), scope="main")

# Duplicated into every worktree by default — no annotation, no naming.
k8s_yaml(helm("chart", name="wt-helm", values=["chart/values.yaml"]))

# Exception 2 — "only in worktrees": branch-local tooling, built/run from
# that worktree's checkout. Never exists in the main run.
local_resource(
    "admin-bff",
    cmd="go run ./cmd/bff",
    deps=["admin/"],
    scope="worktree",
)
```

Naming contract: authors NEVER write clone identity. Tilt derives, per
worktree, all of: engine manifest (`wt:<worktree>_<name>`), cluster objects
(`<name>-wt-<worktree>`), image lineage (scoped ImageMap, per-run build
repo/tag), Service DNS, port-forward. The UI shows the autogenerated
prefixed names (already implemented: `internal/tiltfile/worktree/display.go`).
The one name coupling that remains is upstream's own docker_build-ref-matches-
chart-image rule — single-tilt coupling, not worktree coupling. The example
chart currently renders `repository: wt-helm/api` (an invented prefix); it
must be de-coupled to `repository: api` (Step 5).

Author-visible contract (the one table):

| scope=        | main run               | worktree run                          |
|---------------|------------------------|---------------------------------------|
| `"main"`      | applies bare object    | dropped; never cloned                 |
| `"worktree"`  | dropped                | applies clone only (`-wt-<worktree>`) |
| `"all"` (def) | applies bare object    | applies clone only                    |

Everything downstream — ImageMap identity, build context (run cwd), live
update targeting, Service routing — derives from this table plus the run's
worktree name. Tiltfile authors never name clones.

## Steps

1. **Delete the runtime fallback; replace with deterministic image rewrite.**
   - Remove `reconciler.go:568-591` (the `if !replaced && spec.Worktree != ""`
     block) — injection returns to the plain upstream path.
   - In the same apply-time mutation stage that already mutates the worktree
     YAML (`stampWorktreeClones`, called from both the inline-YAML path and
     the ApplyCmd path in `reconciler.go`), add a deterministic rewrite: each
     clone workload's container image refs whose repo matches the STABLE
     selector (scoped selector minus `container.WorktreeTagSuffix(worktree)`
     token) are rewritten to the scoped selector repo, BEFORE
     `InjectImageDigest` runs. The applied YAML then references exactly what
     the run's ImageMap will inject — visible, not inferred.
   - Acceptance: no match-retry semantics anywhere; unit test proves the
     rewrite (stable repo in chart YAML → scoped repo in the stamped YAML);
     the existing `TestWorktreeCloneStamping_InjectsStableImageRef` asserts
     the same end state via the rewrite, not the fallback.

2. **Pin scope-driven instantiation for k8s (loader seam exists; verify + pin).**
   - `scope="main"`: worktree runs drop the YAML; main's objects are never
     cloned and never referenced by worktree runs.
   - `scope="worktree"`: main drops it; worktree runs apply clones only.
   - `scope="all"`: main applies bare; worktree runs apply clones only.
   - `k8s_resource` grouping in worktree runs must reference the clone
     KubernetesApply/discovery names so live update and port-forwards wire to
     clones, not main's objects. Verify in the live example; add loader tests
     next to the existing scope tests in `internal/tiltfile/k8s.go` tests.

3. **Live update + build wiring follows scope (the "should live update" contract).**
   - A worktree run's `LiveUpdateSpec.Selector.Kubernetes`
     (discoveryName/applyName/imageMapName) must point at the CLONE objects
     (`api-wt-wt-a` / `wt:wt-a_api` / `wt-helm_api-wt-wt-a`). Re-stamp these
     derived names in the boundary pass the same way clone manifest names are
     re-stamped (pattern: `renameDerived` in
     `internal/tiltfile/worktree/boundary.go`).
   - `scope="main"` images never feed worktree pods; `scope="worktree"`
     resources never live-update from main's checkout (their file watches
     live in the worktree dir — already true via per-run cwd).
   - Acceptance: edit `.worktree/wt-a/api/main.go` → only `wt:wt-a_api`
     live-updates (already observed live); pin with a liveupdate-selector
     unit test asserting clone targeting.

4. **Service traffic: mutation is the mechanism; gateway is the access layer.**
   - Keep clone Services (`<svc>-wt-<worktree>` with the worktree label
     selector) + the sibling DNS rewrite (clone env/args refs to cloned
     siblings resolve to clone Service names). Live-verified: 30000→wt-b pod,
     30001→wt-a pod, 30002→main pod.
   - Load balancer: the existing worktree gateway
     (`--gateway-port`, `<branch>.tilt.localhost` URLs) is the local-access
     layer for browsers/tools; it complements Service mutation, it does not
     replace it. No per-worktree LB objects are injected for ClusterIP
     charts.
   - Notation escape hatch (deferred): only if a real case cannot be
     inferred (e.g. sibling hostnames inside ConfigMap data — the current
     rewrite covers container env/args only). Do not build preemptively.

5. **Re-verify end-to-end + document.**
   - De-couple the example: `examples/worktrees-helm/chart/values.yaml`
     `image.repository: wt-helm/api` → `api`; Tiltfile
     `docker_build("wt-helm/api", ...)` → `docker_build("api", ...)`. No
     other chart/Tiltfile changes — duplication, clone names, and image
     lineage stay autogenerated.
   - Fresh `tilt up --worktrees`; assert clone siblings, per-worktree images,
     scoped live reload both directions, distinct ports, `tilt down
     --worktrees` cleans clones.
   - `docs/worktrees.md`: the naming contract (vanilla names, autogenerated
     clone identity), the scope table, the traffic design (mutation +
     gateway), and the no-fallback contract.
   - Full test sweep of touched packages:
     `./internal/controllers/core/kubernetesapply ./internal/tiltfile/...
     ./internal/engine/configs ./internal/tiltfile/worktree`.

## Verification

- Per step acceptance above; the whole plan is done when the helm example
  runs with: no fallback code in `reconciler.go`, all four scope rows
  observable in one session, live update scoped per worktree, and every
  behavior pinned by a test that fails on the plausible regression.
- Live check: `kubectl get deploy -o custom-columns=NAME:.metadata.name,IMAGE:.spec.template.spec.containers[0].image`
  shows stable + clones with distinct per-worktree image lineage.

## Out of Scope

- RefSet tag-token image lineage (same repo, `-wt-` tag) — alternative
  design; rejected for now because it requires ImageMap CR name overrides
  (name derives from selector) and the build-side seam (`RefSet.WithWorktree`)
  was never wired into the build controllers.
- Notation for non-inferable refs (ConfigMap hostnames) — deferred until a
  concrete case exists.
- Gateway URL routing changes (`<branch>.tilt.localhost`) — already built;
  only documented here.
